# kiko

一款基于 **Vue 3 + Tiptap 3 + Tauri 2** 的桌面日记应用，界面清爽、支持富文本编辑、图片插入、标签分类与全文搜索。数据以纯 JSON 文件保存在本地，无需数据库，方便备份与迁移。

## 功能特性

- **富文本编辑**：基于 Tiptap 3 的 Notion 风格编辑器，支持标题、列表、引用、代码块、表格、任务列表、图片、分割线等
- **块操作**：鼠标悬停在块左侧出现 `+` / `⋮⋮`。`⋮⋮` 可按住拖动整块，单击打开菜单（文字色/背景色、Turn Into 转换、复制、复制锚点链接、删除）
- **图片支持**：粘贴/拖拽/选择插入图片，编辑区可缩放图片、设置对齐与图注；图片按内容哈希去重
- **标签系统**：为日记添加标签，按标签筛选，标签可重命名/删除；内置系统标签「无标签」（始终存在、不可重命名/删除），选中它即筛出**没有任何标签**的日记
- **全文搜索**：按标题与正文搜索，支持防抖
- **日期管理**：内置日历选择器，支持日/月/年/年代视图
- **目录侧栏**：正文含标题时显示目录、可跳转，位置可左右切换；显隐按**编辑器实际可用宽度**判断（≥860px），与屏幕分辨率/缩放比例无关
- **日期区间筛选**：按开始/结束日期筛选日记（可只填一端），预置本月/上月/近 30 天/今年/去年/全部时间；可与标签、关键词组合，并汇总所选标签在该区间内各写了几篇
- **排序**：按日期 + 创建时间戳升/降序
- **主题**：应用浅色/深色主题；编辑器可独立切换深色模式
- **数据管理**：
  - 导出数据到用户指定位置（系统「另存为」对话框）
  - 从 JSON 文件导入
  - 数据目录可自定义，切换时智能检测目录内容
  - 一键扫描并清理空目录
- **本地优先**：所有数据以 JSON 文件保存在本地，不上传云端

### 编辑器快捷操作

选中整块（点 `⋮⋮` 或拖拽后）时生效，普通文本编辑不受影响：

| 快捷键 | 作用 |
|---|---|
| `Ctrl/Cmd + D` | 复制当前块 |
| `Ctrl/Cmd + C` | 复制当前块文本 |
| `Ctrl/Cmd + L` | 复制当前块锚点链接 |
| `Backspace` | 删除当前块 |

在编辑页按 `Ctrl/Cmd + S` 可直接保存日记，**保存后停留在编辑页**，可以继续写作；「保存日记」按钮保持「保存并返回列表」的原有行为。

按 `Ctrl/Cmd + /` 或输入 `/` 可弹出 slash 菜单，按 ↑↓ 选择、Enter 确认、Esc 关闭；菜单按 **Style / Insert / Upload** 分组。

> 块带有稳定的 `id`（`data-block-id`），用于生成锚点链接。首次打开旧日记并保存后，正文 JSON 会补充该属性。

### 目录侧栏的显隐

目录不再按窗口（视口）宽度判断，而是由 `NotionLikeEditor` 用 `ResizeObserver` 量出**正文区的实际可用宽度**：

- 正文区 ≥ 860px：显示目录，正文固定 708px，目录一侧至少 132px，对侧留白最少 20px；
- 正文区 < 860px：目录自动隐藏，正文居中（正文按 708px 上限自适应收窄）；
- 文档没有标题时不占列宽，正文保持居中。

这样在高 DPI 笔记本（如 200%~250% 缩放、全屏 CSS 视口只有 1200 多 px）上也能正常显示目录，不必再把窗口拉到 1280px 以上。

### 按日期区间 + 标签统计

工具栏的「日期过滤」用来只看某段时间内写了什么：

- 填「开始日期 / 结束日期」；只填一端表示「该日期之后 / 之前」，两端都空表示不限，起止填反会自动交换；
- 预置区间：本月 / 上月 / 近 30 天 / 今年 / 去年 / 全部时间；
- 与「标签过滤」「关键词搜索」**同时生效**（取交集）。

筛选生效后列表上方出现汇总条：区间 → 每个所选标签在该区间内各写了几篇 → 合计篇数与字数。同一篇日记挂多个标签时，各标签分别计数，合计篇数按日记去重。

### 面包屑与「退回」

页面顶部有面包屑，记录当前位置：

- **日记页**：`首页 › 日记`（带标签筛选时显示 `标签：旅行`，多标签显示 `标签：旅行 等 N 个`，仅有日期区间时显示 `日记 · 按日期`）；
- **编辑页**：`首页 › 日记 › 编辑：标题`（从首页日历进入时只显示 `首页 › 编辑日记`）；
- **标签页 / 设置页**：`首页 › 标签` 或 `首页 › 设置`。

点祖先节点可直接跳转。**「退回时哪来的就回哪」**：从日记列表进编辑再返回，标签筛选、日期区间、滚动位置、已加载条数都原样恢复；从首页日历进编辑再返回，日历选中日期和滚动位置也恢复。编辑页有未保存更改时，点面包屑会先问「保存并离开 / 不保存」，不会丢内容。

## 快速开始

```bash
# 安装依赖
npm install

# 启动开发模式（同时启动 Vite + Tauri 窗口）
npm run tauri:dev
```

## 构建发布

```bash
# 打包为 NSIS 安装程序（产物在 src-tauri/target/release/bundle/nsis/）
npm run tauri:build
```

> **构建说明**
> - `build` 脚本会把 `TEMP`/`TMP` 重定向到项目内的 `.tmp` 目录，避免部分环境下 esbuild 无法删除系统临时文件导致构建失败。
> - 首次打包 NSIS 需要从 GitHub 下载 `nsis-3.13` 与 `nsis_tauri_utils`，网络受限时可能超时。可先手动下载并解压到 `%LOCALAPPDATA%\tauri\NSIS` 后再构建。

## 自动更新

应用内置基于 `tauri-plugin-updater` 的自动更新，更新源为 GitHub Releases 上的 `latest.json`。

- **启动时检查更新**：默认**关闭**，可在「设置 → 关于」中开启
- **手动检查**：「设置 → 关于 → 检查更新」
- 发现新版本后点「下载并安装」，安装阶段程序会自动退出，重新打开即为新版本
- 正在编辑日记时**不允许**直接安装更新（安装会退出进程，而本项目保存是手动的，未保存内容会丢失）

> ⚠️ **签名私钥**
> 更新包必须签名，公钥写在 `tauri.conf.json` 的 `plugins.updater.pubkey`（可公开）。
> 私钥默认位于 `~/.tauri/kiko.key`，**必须离线备份**：私钥一旦丢失，已安装的用户将永远收不到更新。
> 私钥绝不能提交到仓库。

### 发布新版本

```bash
# 1. 先提交所有改动（脚本要求工作区干净）
# 2. 指定签名私钥
$env:TAURI_SIGNING_PRIVATE_KEY = "$env:USERPROFILE\.tauri\kiko.key"
# 3. 一键构建 + 打标签 + 上传
npm run release -- 1.1.0 --notes .tmp/notes.md
```

脚本会依次：同步三处版本号（`package.json` / `tauri.conf.json` / `Cargo.toml`）→ 构建带签名的安装包 →
生成 `latest.json` → 提交版本号并打标签 → 推送 → 上传 GitHub Release。

常用参数：`--dry-run` 只构建并打印 `latest.json`；`--skip-build` 复用已有构建产物。

> GitHub CLI 未登录时脚本会尝试从 `git credential` 读取令牌；也可直接设置 `GH_TOKEN`。

## 数据存储

### 数据目录

默认在**运行目录**下的 `data/kiko/`，可在「设置 → 数据目录」中通过目录选择器修改。

配置文件：运行目录下的 `kiko.config.json`。

**切换目录时的行为**：

| 目标目录状态 | 行为 |
|---|---|
| 空目录 | 迁移当前数据过去 |
| 已有 kiko 数据 | 弹窗询问：覆盖（用当前数据替换）/ 取消（直接使用目标目录数据） |
| 非 kiko 数据 | 拒绝切换并提示 |

- 选择「覆盖」后，会再询问一次**是否删除原数据目录**
- 目录判定会校验 `meta.json` 内容结构（必须是含 `id`/`date`/`dirName` 字段的数组）与 `diaries/` 目录，避免误判
- 兼容两种布局：所选目录下套 `kiko/`，或所选目录本身就是数据目录

### 目录结构

```
data/kiko/
├── meta.json                 # 元数据索引（id/标题/日期/标签/字数/摘要/时间戳）
├── search.json               # 搜索索引（id → 纯文本）
├── config.json               # 应用配置（主题/用户信息/标签列表）
└── diaries/
    └── {年}/{月}/{日期}/      # 按日记归属日期分层，如 2026/10/2026-10-20
        └── {创建时间戳}/       # 每个日记一个目录
            ├── {创建时间戳}.json    # 正文（Tiptap JSON）
            └── imageFiles_{创建时间戳}/   # 图片（仅在有图片时创建）
                └── {创建时间戳}_{哈希}.{ext}
```

### 设计要点

- **元数据与正文分离**：启动时只加载 `meta.json`（轻量），正文按需读取，支持懒加载
- **图片按内容哈希去重**：相同图片只保存一份，正文中多处引用同一文件
- **编辑不改变创建时间戳**：日记创建后目录名固定，修改日期会整体迁移目录
- **无图片不建目录**：正文没有图片时不会生成 `imageFiles_*` 目录
- **可清理空目录**：删除日记后残留的空文件夹可在设置中一键扫描清理

## Tauri 命令

**日记数据**

| 命令 | 说明 |
|---|---|
| `load_meta` | 加载全部日记元数据 |
| `get_body` | 按 id 读取正文 |
| `save_diary` | 保存日记（返回 id + 创建时间戳） |
| `delete_diary` | 删除日记及其目录 |
| `search_diaries` | 全文搜索（标题 + 正文） |

**配置与数据目录**

| 命令 | 说明 |
|---|---|
| `load_config` / `save_config` | 读写应用配置 |
| `get_data_dir` | 获取当前数据目录 |
| `inspect_data_dir` | 检查目录状态：空 / kiko 数据 / 其他 |
| `set_data_dir` | 切换数据目录（migrate / overwrite / keep） |
| `remove_data_dir` | 删除原数据目录（确认清理时） |
| `list_empty_dirs` | 列出空目录 |
| `remove_empty_dirs` | 清理空目录 |

**文件**

| 命令 | 说明 |
|---|---|
| `write_text_file` | 把文本写入指定路径（导出数据用） |

## 注意事项

- **安全软件拦截**：若 Windows 上杀毒软件（如 360 安全卫士）拦截文件写入或内存映射，可能导致启动或保存失败。建议将程序目录加入信任区；本项目已从 redb 迁移到 JSON 文件存储以规避该问题。
- **数据备份**：直接复制 `data/kiko/` 目录即可完整备份；也可用「设置 → 导出数据」导出 JSON 到指定位置。
